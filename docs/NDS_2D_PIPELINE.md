# Nintendo DS 2D graphics pipeline

## Implemented stages

- `NdsDisplayControl` retains Engine A/B display registers and per-BG scroll/window/blend state.
- `Nds2dTextBgFetcher` produces 256-pixel source lines for supported text backgrounds, using live mapped BG VRAM and palette RAM. It supports 4bpp/8bpp, tile-map size, flips, scroll and BG mosaic. With DISPCNT bit 30 enabled, 8bpp text tiles use the selected extended BG palette: BG0 selects slot 0/2 and BG1 slot 1/3 via BGxCNT bit 13; BG2/BG3 use slots 2/3. BGxCNT bit 7 remains the tile-depth selector, so 4bpp text tiles continue to use standard BG palette RAM. Engine A uses VRAM E/F/G and Engine B uses VRAM H MST=2; palette reads are internal to the display pipeline and do not expose those VRAM banks to guest CPUs. Missing or ambiguous palette allocations fail closed.
- `Nds2dAffineBgFetcher` renders classic affine tiled BG2/BG3 in Modes 1, 2 and 4, plus extended affine tiled BGs in Modes 3/4 (BG3) and 5 (BG2/BG3). Classic maps use one-byte entries; extended maps use 16-bit entries with ten-bit tile indices and horizontal/vertical tile flips. With DISPCNT bit 30 enabled, the upper map-entry nibble selects one of 16 256-color palettes in that BG's 8 KiB slot; color index zero remains transparent. Engine A palettes come from VRAM E slots 0–3 or VRAM F/G upper/lower slot pairs selected by OFS; Engine B palettes come from VRAM H MST=2. The display pipeline reads the physical VRAM backing without exposing these allocations to guest CPUs, and missing/overlapping palette banks fail closed. Extended affine bitmap modes support indexed 8bpp pixels via standard BG palette RAM (index zero transparent) and direct-color 16bpp RGB555 pixels (bit 15 is the alpha/opaque flag). Bitmap bases use 16 KiB BGxCNT blocks, sizes are 128×128, 256×256, 512×256 or 512×512, and BGxCNT overflow wraps each axis; bitmap surfaces larger than 128 KiB are Engine A only. Tile and bitmap paths share signed PA/PB/PC/PD 8.8 coefficients, signed 19.8 BGxX/BGxY references, PB/PD scanline accumulation and BG mosaic.
- `Nds2dObjFetcher` reads the two 1 KiB OAM tables (Engine A at `0x07000000`, Engine B at `0x07000400`) and rasterizes tiled and bitmap OBJ from the corresponding OBJ VRAM windows. Tiled OBJ supports 4bpp/8bpp, 1D/2D character mapping, size/shape, clipping, non-affine flips, signed 8.8 affine matrices, double-size bounds, mosaic, palette transparency, semi-transparent metadata and OBJ-window coverage. Bitmap OBJ is direct RGB555 with alphaBMP in pixel bit 15 and alphaOAM in Attr2[12:15]; it supports 2D 128/256-dot mapping (32 KiB window) and 1D mapping (128-byte character-name boundary, 256 bytes on Engine A with DISPCNT bit 22; Engine B is fixed to 128 KiB). AlphaOAM zero suppresses the whole OBJ; visible bitmap pixels use effective EVA=`alphaBMP*(alphaOAM+1)`.
- `Nds2dBgCompositor` combines BG and OBJ candidates per pixel. It applies WIN0/WIN1/OBJ-window/outside masks, BG/OBJ priority, the OAM-index OBJ tie-break, backdrop selection and alpha/brightness effects. Semi-transparent OBJ and bitmap OBJ require an eligible BG/backdrop second target; another OBJ is never used as an OBJ alpha target. Bitmap OBJ uses its per-pixel/OAM alpha coefficient and does not consume BLDALPHA factors.

For equal BG priority values, BG0 precedes BG1, BG2 and BG3. An OBJ with the same 2-bit priority is in front of a BG; among OBJs with equal priority, lower OAM index wins. The character mapping and OAM bit fields follow the DS video description in [GBATEK](https://mgba-emu.github.io/gbatek/).

## Explicit limits

Affine matrices are read from the 32 interleaved PA/PB/PC/PD OAM groups selected by Attr1[9:13]. Each output pixel is reverse-mapped from the destination bounding box around its center into source coordinates; transformed texels outside the source rectangle remain transparent. Bitmap OBJ mapping 3 and nonzero bitmap color-depth selection are rejected explicitly. 3D BG0, forced blank, the per-scanline OBJ/pixel evaluation budgets, and hardware-accurate PPU fetch arbitration are not implemented. Affine reference accumulators advance at scanline boundaries and visible-line BGxX/BGxY writes replace the current internal origin; VBlank reference-copy edge timing remains a simplified frame-boundary model. OBJ-window coverage is supported as a mask input. The two uppermost OBJ pixels are preserved independently per X for layer ordering and BG-target resolution, never for OBJ-over-OBJ alpha; the desktop SDL host now consumes the compositor through the scanline C bridge and presents the two RGB555-derived screens as streaming textures. This validates desktop presentation of the current guest display state, but the host still does not execute the Platinum banks, so it does not constitute a real-game frame or a boot result. Android surface presentation remains unconnected. A line that encounters an enabled unsupported OBJ mode is rejected without changing the caller's output buffer.


## Desktop SDL presentation

The desktop host no longer draws placeholder rectangles. Each frame it requests all 192 visible scanlines from Engine A and Engine B through `oracis_host_runtime_render_scanline`, expands the 5-bit RGB channels to 8-bit and uploads the resulting 256×192 buffers to SDL streaming textures. Nearest-neighbour scaling preserves the DS pixel grid. If any line reports an unsupported mode or memory/fetch failure, the host logs the first diagnostic and does not present a partially composed frame.

This is a presentation integration milestone only. The current host does not yet run the compiled Platinum banks, and a real-game frame has not been observed. The Android rendering surface is also not wired to this path.
